# Krosforge 0.0.5

- Prioritize the newly created character in the immediate creation response, so the native client does not select an older character instead.
- Keep the regular character list in a stable order.
- Recover the character list in the same native window after a rejected selection, including creation of the first character.
- Show the character list when entering or reentering the local server instead of automatically selecting a remembered character.
- Update the managed client copy atomically without recopying the whole installation.

- Enter the configured local map with an owned character and restore its saved cell and direction when reconnecting.
- Migrate existing SQLite data with a verified backup before adding character locations.
- Initialize the character display with explicit local attributes and experience thresholds read from the installed client.
- Move with runtime-validated paths and restore confirmed positions after reconnecting.
- See other local profiles enter, move and leave the same map.
- Travel in both directions between the two configured exploration maps.
- Keep map events ordered and isolate a stalled connection from other local profiles.

## Validation and limitations

Exploration covers two configured maps and their connection. Combat, NPC interactions, quests, inventory gameplay, team automation and multiplayer between computers are not included. Native acceptance for this development cycle focuses on Portuguese on Windows; existing launcher languages remain available.

Schema 2 cannot be opened by older launchers. Pre-migration backups are stored under `Krosforge-data/backups`; see [database recovery](../docs/world-entry.md#database-migration-and-recovery) before attempting a downgrade.

Windows x64 packages contain one portable `Krosforge.exe` inside a ZIP. Reference client build: `3.7.14.18`.
